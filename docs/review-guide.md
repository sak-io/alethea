## 2. The system on one page

```
 Claude Code session                       other MCP hosts
   | hooks (JSON on stdin)                       |
   v                                             v
 engram/hooks/engram_hook.py            engram/mcp_server.py   mnemo (engram/cli.py)
   \________________________  ______________________/            |
                            \/                                    |
                  engram/client.py  (fail-soft: never raises)  <--/
                            |   newline-delimited JSON
                            v
        Unix socket (0600, dir 0700)   or   loopback/TCP + token
                            |
                   engram/daemon.py  (single writer, FairLock)
          verbs: remember recall observe briefing reflect forget sleep
                 session_end status dump export_rules ping
                 pending distill_submit reembed
             /           |             |                \
      encode.py     recall.py    consolidate.py      export.py (renders only)
   (gate, dedup,   (lexical+vector  (sleep cycle:
    redaction)      +graph fusion)   replay, gist,
             \           |           downscale, prune,
              \          |           recombine, purge)
               +----> cortex.py  (SQLite WAL + FTS5; schema, activation) <----+
```

Memory kinds and decay: episodic, semantic, procedural, identity (never decays). Activation follows ACT-R base-level learning on strength (`cortex.base_activation`); sleep multiplies strength down at a per-kind rate (`DOWNSCALE_RATE`) and archives below `ARCHIVE_ACTIVATION`.

**Trust boundaries (where hostile input enters):**
1. Anything a user or agent says (prompts, replies, `remember` text) becomes stored text. It is later injected into model prompts (briefing, MCP recall output, exported rules). Stored text is **untrusted**.
2. Local processes talking to the daemon socket/TCP port.
3. The user's own files that the tool edits: Claude Code `settings.json` (installer) and `.claude/engram_learned.md` <!-- verify-guide: runtime --> / `.cursor/rules/...` (export).
4. The working directory a hook or autostart is launched from (Python's `-m` puts it first on `sys.path`).

## 6. What has NOT been independently verified

Be explicit about the limits of the evidence:
- **Every review so far was done by AI agents** (a fresh reviewer agent per task, plus a whole-PR reviewer). No human has read this code. Their findings and fixes are in the commit history. `docs/architecture/reviews/index.md` summarises T01-T21 from the git log only (review texts were not kept as files); the Phase 2 reviews (T22-T24) and the installer review are recorded only in commit messages and in the PR description's "Review history".
- **The hooks have not been run inside a real Claude Code session.** They were exercised by invoking the commands exactly as `settings.json` would, with the JSON shapes from the current Claude Code docs (`docs/architecture/claude-code-hooks-reference.md`). Whether Claude Code expands `${CLAUDE_PROJECT_DIR:-.}` in `.mcp.json` and honours exec-form hook `args` exactly as documented has not been confirmed live.
- **The installer has never been run against a real Claude Code installation** or a real user `~/.claude`; tests use a temporary HOME.
- **Recall quality numbers come from a corpus written by the build agents**, not from real sessions. recall@3 0.953 (tuning set) and 0.833 (held-out) are only indicative.
- **Scale:** write cost was measured up to 20k memories on a loaded sandbox; larger stores and long-lived daemons are untested.
- **The Cursor integration (`mnemo install cursor`) has never run against a real Cursor.** Tests use a temporary HOME and a temporary git repository; file locations, the `mcpServers` shape, the rule frontmatter and reload behaviour are from recalled documentation. `integrations/cursor/hooks.example.json` is an inert labelled sketch. Codex/Gemini/Grok get an MCP-only printed snippet (`mnemo install --print mcp`), also unchecked.
- **Docker:** the image was built and run once in a sandbox (`--network none`, no bridge): healthy, remember/recall inside, token refusal. `docker compose`, the published port and a host-side client were not exercised (`docs/docker.md`, `scripts/test_docker.py`).
- **Platforms:** POSIX only; macOS and Windows are untested (CI is ubuntu only).
- **Permission-denied tests (chmod 000, read-only directory) were skipped** because the sandbox runs as root.
- **The optional local embedder (`ENGRAM_EMBEDDER=fastembed:<model>`, T25) has never run with the real model.** The model could not be downloaded in the build sandbox; the path is verified up to the real `fastembed` import, the real "model cannot be loaded -> hashed fallback" path, and the real `FastEmbedEmbedder` class with a stubbed model call. Real cosine distributions are unmeasured, so every embedder ships the conservative hashed thresholds (ADR 0010). The dedup safety claim under dense embedders rests on a fake dense embedder, not on a real model; the vetoes read text, which is what makes that sufficient.
- **Redaction is pattern based** and misses rare token formats; hashed n-gram embeddings cannot see synonyms (documented gaps).
