# ADR 0010: Embedder plugin loading, containment and per-embedder thresholds

Status: Accepted (T25; revised after review: the first version held the engine lock across embedder calls)

## Context
The default embedder is a hashed n-gram projection; semantic paraphrases miss. `docs/technical-details.md` section 4 makes the `Embedder` a first-class plugin that must never cost the zero-dependency default, must never break the daemon, and must not weaken duplicate safety (a false merge is silent and permanent). The overriding project rule is that a broken memory must never break the session (hooks have a 2 s budget).

An embedder is code outside our control: loading can download for minutes and sleep in the library's own retry loop (measured 40 s with the model hub blocked), a call can be slow or hang forever. The first implementation ran these calls under the global FairLock; a 6 s embedder made `status` and `recall` hit the 2 s hook budget and return offline, and a hung one would have blocked the daemon forever. That design is rejected.

## Decision
1. **Selection.** `ALETHEA_EMBEDDER` is `hash` (default) or `<scheme>:<arg>`. `alethea.vectorize` keeps a registry: built-in lazy schemes (`fastembed` maps to `alethea.embedders_ext:make_fastembed`, imported only when selected) plus `register_scheme(name, factory)`. `openai` is the reserved hook for T26 (one `_LAZY` entry); until then it is an unknown embedder.
2. **No embedder call under any lock.** The daemon computes vectors before taking the engine lock (`encode.embed_for`, `recall.embed_cue`) and passes them in (`embedded=`). Dedup compares the candidates' STORED vectors with the precomputed one. `recombine` uses stored vectors only. The sleep cycle embeds an episode's summary and facts before taking the lock. `encode.similarity` and `_raw_similarity` never call an embedder: without supplied vectors they use hashed ones. Library callers that pass nothing still work (the vector is computed inside `encode()`), which is fine without a shared lock.
3. **Model load in the background.** In daemon mode `configure()` starts a daemon thread that loads the model. While it loads, and after it fails, every call uses the hashed embedder under the HASHED id. The load has a deadline (`ALETHEA_EMBEDDER_LOAD_TIMEOUT`, 120 s); a thread still running at the deadline is abandoned, never joined, and its late result is discarded (token check). A finished load flips new writes to the model atomically. Failed loads are retried in the background with a 30 s to 10 min doubling backoff, started opportunistically by the next request or `status` (a thread start, no waiting).
4. **Bounded calls.** One worker thread with a queue of one runs embedding calls; the requester waits at most `ALETHEA_EMBEDDER_TIMEOUT` (1 s) and a timeout is failure kind `timeout`. A request that finds the worker busy uses hashed immediately. A worker that has been stuck past a whole cooldown is replaced (the stuck daemon thread exits by itself if its call ever returns), so threads stay bounded.
5. **Circuit breaker.** After 3 consecutive failures the model is bypassed (no calls, no waiting) for 30 s, doubling to 10 min. After the cooldown one probe call is submitted to the worker (never run on a request thread); success closes the breaker, failure doubles the cooldown.
6. **One embedder per operation and honest ids.** `vectorize.embed_batch(texts, embedder_id=None)` returns `(id_used, vectors)`. A fallback returns the hashed id, so a configured-but-unavailable embedder never lends its id to hashed vectors (including an explicit id in the configured scheme's namespace). An explicit id that is not the loaded embedder is a legacy/test label: hashed vectors stored under that label (kept so existing callers and tests work; T26 remote ids are in the configured namespace and so are treated as unavailable, not as labels).
7. **Validation and fail-soft.** Vectors are checked (dimension, finite, non-zero) and re-serialised as float32. Any failure falls back to hashed for that call and logs one stderr line per failure kind per process (spec, kind, exception class; never memory text).
8. **Per-embedder thresholds.** `Embedder` declares `NEAR_DUPLICATE`, `SEM_GAIN`, `SEM_MIN_COS`, `RECOMBINE_LO`, `RECOMBINE_HI`; consumers read them through `vectorize.tuning(embedder_id, name, default)`, which only answers for the loaded optional embedder, rejects NaN/inf/out-of-range values (default instead), and `encode.threshold()` is `max(0.88, registered, declared)`. All shipped embedders inherit the hashed values.
9. **Coexistence.** Vector search filters by `embedder_id`; other ids are reachable through FTS only. `recombine` skips pairs with different ids; dedup only compares candidates with the writing embedder's id. Dimensions are arbitrary (mismatched lengths score 0.0). The decoded-vector cache is bounded by total floats.
10. **Safety is textual.** The vetoes work on text. `tests/test_dedup_dense.py` proves it: a fake dense embedder puts adversarial pairs at cosine >= 0.97; a patch forcing cosine 1.0 on every pair still leaves every distinct pair below the threshold; end-to-end `encode()` pairs run per embedder.

## Consequences
- A slow, hung or failing embedder costs recall quality (hashed vectors) but never availability: `tests/test_embedder_daemon.py` runs a real Alethea + Server with a controllable embedder (slow load, slow embed, hang, raise, late return) and asserts every verb answers well inside the hook budget, the first write returns within timeout + 0.5 s, no embedder call happens while the engine lock is held, the breaker makes no calls during cooldown and recovers, and threads stay bounded over 200 failing calls.
- Thresholds for real models are NOT tuned (cosine distributions unmeasured; the real model could not be downloaded in the build environment). Declared `NEAR_DUPLICATE` below 0.88 is clamped, so tuning can only make merging stricter.
- Rows written while loading or falling back carry the hashed id; they coexist with model rows and are lexical-only to model queries until `mnemo reembed` (T26). `(embedder_id, vector length / 4)` per row is what T26 needs.
- Abandoned load threads and replaced workers are daemon threads that cannot be killed; their count grows by at most one per retry/cooldown (at most every 30 s to 10 min).
- Writes during loading, the first failures and cooldowns lose model vectors; the cost is measured only against the hashed baseline, not against real-model quality.
- Privacy: `fastembed` runs on-device; only the package's model download touches the network.

## Alternatives considered
Importing `fastembed` at start (breaks "stdlib path never imports extras"); calling the embedder under the lock with a timeout (still serialises every other verb for the timeout); running the embedder in a subprocess (kills hung calls for real, but adds an IPC protocol and a process to manage; a candidate if abandoned threads ever matter); trusting a dense cosine for merging (rejected: models place opposite statements close together, which is why the vetoes stay).
